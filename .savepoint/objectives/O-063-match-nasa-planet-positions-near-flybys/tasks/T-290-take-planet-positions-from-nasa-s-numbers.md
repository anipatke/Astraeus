# Take planet positions from NASA's numbers

## Outcome

Every planet's series (Mercury to Neptune, as Pluto already is) is a fit of its system barycentre from JPL Horizons DE441 over 1950 to 2045, and each planet with a moon system adds its own offset from the barycentre from its moon package when that package is loaded (Pluto's binding made the rule for every planet). T-289's measurement test then shows the gain, and every planet's accuracy and provenance text states the newly measured figures.

## User Check

None on screen; the owner reads the before/after table in Technical Evidence.

## Done When

- `tools/import/planet-fits.mjs` takes Horizons as the one source for every planet (no VSOP87A path left for the eight planets; one rule, no per-planet special case beyond Pluto's existing one becoming general); the planet data is regenerated by the importer, not hand-edited.
- Each planet with a moon system (Mars, Jupiter, Saturn, Uranus, Neptune; Pluto already) gets the barycentre-offset binding when its moon package is loaded; without it the planet is the barycentre and its card/provenance says so with the measured wobble.
- `tests/planetAccuracyFlybys.test.ts` asserts the new errors at the flybys and across 1950 to 2044: with the moon package loaded within the fit tolerance (about 1 km, state the measured value); without it within the measured wobble. `planetFits.test.ts` compares with Horizons instead of the series.
- Planet provenance (source DE441, retrieval date, measured figures, known limits) replaces the old six-date figures; README accuracy rows updated; CHANGELOG under Unreleased (0.8.1) states the data change and the measured gain.
- Download size measured: `planets.json` before and after, engine first-download budget (`tools/validate/engine-budget.mjs`) still met; if over budget, stop and report rather than raising a limit.
- Earth (EPV00 model) measured against Horizons the same way and reported; changed only if the same rule naturally covers it, otherwise recorded as a finding for the coordinator.
- No public API change; `scene.load`/`out-of-span` behaviour unchanged; Apollo and other demo determinism tests pass (any changed golden values explained by the measured position change, never loosened).
