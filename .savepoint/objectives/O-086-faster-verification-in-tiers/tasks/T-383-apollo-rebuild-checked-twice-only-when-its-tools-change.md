# Apollo rebuild checked twice only when its tools change

## Outcome

The Apollo 11 reconstruction runs once per `npm test`; the second, byte-identical run (the determinism proof) happens only when the reconstruction tools or raw inputs differ from the last sources proven deterministic (AH-31; Gemini S-07: the double run is about 70 s of CPU).

## User Check

None visual.

## Done When

- `npm run apollo11:reconstruct` (`tools/apollo11/run.mjs`) runs `reconstruct` twice, fails without writing anything if the two outputs differ, and otherwise writes the generated files as today plus `packages/astraeus-demo-apollo11/tests/fixtures/apollo11ToolsProven.json`: `{ "sha256": <hash>, "files": [<sorted relative paths hashed>] }`. The hash covers every file in `tools/apollo11/` (sorted by path, content bytes) and `data/apollo11/raw/*.json`.
- In `apollo11Reconstruction.test.ts`, `beforeAll` computes the same hash (one shared helper, `tools/apollo11/toolsHash.mjs`, imported by both `run.mjs` and the test; not in `run.mjs` itself, whose top level runs the reconstruction). When it equals the fixture's hash the second `reconstruct` is skipped and the "produces byte-identical output on a second run" case is reported as skipped with a reason naming the fixture (`it.skipIf`), not passed vacuously; when it differs, the second run happens and the case asserts byte identity as today.
- Every other case in the file is unchanged.
- Proof both ways recorded: (a) as committed, the second run is skipped (file time before/after, same machine); (b) a whitespace-only local edit to one `tools/apollo11/*.ts` file makes the second run happen and pass; revert.
- The fixture is generated by running `npm run apollo11:reconstruct`, and `git diff` shows no change to any generated data or `docs/APOLLO11_RECONSTRUCTION.md` from that run.
- Gates per `docs/agents/verification.md`.
