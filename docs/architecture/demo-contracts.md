#### Spike 04 shower fixtures (O-011) and the G-004, G-005 additions (O-015, O-016)

Reconciled by T-040 from the drift notes of T-036 to T-039, T-051 to T-055 and I-027; the paragraphs from "Measured orbits from a second source" to "Public site and launch" were added on 2026-10-17 for the notes after T-040 (T-056 to T-064, I-019, I-022, I-030; see T-065's Design reconciliation entry). Each paragraph names its Task. Perseids and Geminids reuse the contracts above; the generic changes the spike needed are listed here, and every one is optional per experience, so an experience that does not set it renders as before (checked by the integration browser run, `docs/evidence/o011-integration-*`).

**Window strip and camera reach (T-036, T-037).** (The strip was removed in O-020 T-084; see "Shell layout (O-020)" below.) The timeline window was one block above the slider (tinted band, area-filled rate curve, peak diamond, name), 44 px on desktop and 56 px on phone, with the band clickable to seek and open details; presentation only, no contract change. I-019 (`c19aacf`) redrew it as a single hump (one area-filled curve with the peak diamond) under one caption (`.timeline-window-caption`: the window's label and "peak <rate>" from its own samples, via `windowPeakRateText`), still derived only from the window data. `ExperienceDefinition.camera?: CameraReach` (`maxFocusDistance` and `far`, in Earth radii) is checked by `validateCameraReach`; `SceneRuntime` carries `cameraReach`; `focusLimits` is exported. The name check covers the new field. A new made-up entry `?experience=synthetic-belt` (`syntheticBeltDefinition`) proves a Sun-centred group beyond the old limit is visible.

**Shell layout (O-020: T-079, T-080, T-081, T-082, T-083, T-084, T-085, T-086, T-090).** Reconciled at T-082; the shell stays generic (ARCH-01, no experience names).
- *Top bar (T-079).* `TopBar` (object picker, Info, camera preset buttons, Scale) plus `DeveloperToggle`; icon buttons, one compact row. `ExperienceObject.listed` and `partOf` decide which objects the picker lists and which orbits are reached from their body (the reachable-orbit rule is part of the shell and experience contract). No shipped experience offers three scales, so a two-scale experience gets a toggle and the menu is live only when `scaleChoices` lists three ids.
- *Scale explanation (T-079, T-085).* The old "what does this scale mean" panel is the toggle's and each menu item's tooltip; there is no control for a single scale, and an explanation sits beside a choice.
- *Timeline (T-080).* `TimelineBar.css` owns the timeline's rules; `TimelineExpanded` is exported and reused by the phone drawer; the info panel's `--shell-timeline-space` is measured from the timeline (`useTimelineSpace` in `AstraeusShell`; the `style.css` defaults are fallbacks that the timeline's `:has` rules override).
- *Phone (T-081).* `phoneLayout.ts` is the one place that decides "phone" (a narrow screen or a short touch screen, which includes a landscape phone) and holds the live layout numbers; the shell sets `data-phone`, and `phone.css` keys on it: a name pill and cog, a top drawer (the whole control row, closed after a pick), a timeline drawer (speed slider, events), information and story panels as bottom sheets above the timeline, Sources in their own collapsible section. Phone speed shows compact rates. Safe-area insets are used but cannot be emulated headlessly.
- *One control look (T-081).* `controls.css` owns how every control looks (36 px desktop, 44 px touch); components set layout only. The Developer panel is outside it.
- *Activity glow (T-084, T-086).* The window strip is gone. `timelineGlow.ts` turns the experience's rate profile into a gradient inside the scrubber track (a `.timeline-glow` behind the range input, played part clipped at the playhead, peak diamond above the line); with no rate it draws a steady line at the `steadyBrightness` setting. Settings for it live in the developer panel.
- *Developer panel (T-090).* Its settings are grouped and folded; Frame rate sits under "Under the hood". Presentation only.
- *Browser driver (T-083).* `tools/validate/driver.mjs` is the one place that knows the interface; scripts never find or operate controls themselves, enforced by `driver-guard.mjs` through `tests/browserDriverGuard.test.ts` (details in `docs/BROWSER_CHECKS.md`).
- *Tap to focus (O-022).* Readouts on the canvas: `data-pick-target` (the last object a tap landed on) and `data-pick-hover` (the object under a mouse, empty for touch or when a button is down); the canvas cursor is `pointer` over a target. `SceneControls.hoverBrightness` (default 1.4, limits 1 to 3, Developer > Labels) brightens a hovered name with an inline `filter: brightness()`. Small body-set moons that are not Object-list entries fly through `onCameraRequest` on the first tap and the picker keeps its previous choice: accepted, because the picker cannot list them (O-022 Decision 4). The O-025 two-tap rule for set moons is removed (`membersToName` no longer takes a tapped member; hover and near-zoom naming remain). The driver gained `tapBody`, `tapLabel`, `dragAcross`, `pinchAt`, `hoverBody`, `pickTarget`, `pickHover`, `sceneCursor` and the target finders; `tools/validate/browser-tap-focus.mjs` proves them (mapped in `docs/BROWSER_CHECKS.md`).
- *Embedded look (T-082).* When the page is framed (`embedded.ts`: `window.self !== window.top`, any doubt counts as framed), the shell sets `data-embedded` and `embedded.css` slims the bars (30 px desktop controls, a tighter top bar and one slim timeline line; a phone-sized frame keeps its pill, drawers and 44 px targets with tighter margins). Detection rather than an address flag, because the portfolio's embedded addresses are public and fixed; full screen carries `data-embedded="false"` and is unchanged.


**Listed-orbit group (T-052).** `createListedOrbitGroup` (`src/core/listedOrbitGroup.ts`) sits beside `createOrbitGroup` and implements the same `PointGroup`, with extras `recordIdAt` and `meanAnomalyDegAt`. It takes a list of per-member orbits, propagates each through the unchanged `TwoBodyAdapter` and states each member's State body as `<group id>:<recordId>`. Phase rule (owner decision 2026-10-13): members are spread evenly in mean anomaly at a reference time, with an optional model concentration of a fraction of members near the parent's mean anomaly (an orbital phase band, not a blob on the comet). `TwoBodyAdapter` exposes no gravitational parameter, so the group probes mu through `elementsToState`; an explicit accessor is a possible small later change. The measured stream is not a propagation of each observation epoch to one time: that scatters members 22 to 32 AU from the Sun (T-051), so orbit geometry, not the snapshot, carries the encounter. The CAMS workbook uses the 1904 date system and CAMS gives no true anomaly.

**Eccentric path sampling and the marker rule (T-054).** `PathSpec.sampling?: EccentricSampling` (eccentricity, period, periapsis time; `eccentricPathTimesUtcMs` and `eccentricAnomalyFromMean` in `sunCentredSources.ts`, 512 samples by default, fixed spans only) samples a long orbit evenly in eccentric anomaly; such a path is centred by the middle of its extremes and framed whole (`fitDistance`, margin 1.05). The marker rule (`BodyMarkerSettings`, `drawsAsMarker`, `projectedRadiusPx` in `bodyDraw.ts`; threshold 3 px, dot 6 px; `?markerpx=`; Developer slider) swaps a body whose projected radius is under the threshold for a labelled dot each frame. It is presentation only and never feeds State or metrics (ARCH-02). Visible effect on existing experiences: at True overview the Moon (Earth-Moon), Io (Jupiter-Io) and Earth (shower scenes) draw as markers; Apollo's default and Readable views are unchanged. The catalogue now holds a body that is not a planet: `swift-tuttle` (Sun child, no GM, two-body from published elements, accuracy judged as a fraction of its distance from the Sun, 1% line, instead of body diameters). Any code that enumerates the catalogue for bodies circling the Sun sees it; the shower builder skips a body whose full turn it cannot find (`turnSpanOrNull`).

**The sky (T-051, T-053).** `ExperienceDefinition.sky?: SkySettings` (`visible`, `starBrightness`, `milkyWayBrightness`, `milkyWay`) is on by default; the Milky Way picture is off by default (owner, 2026-10-15; its softness against the stars is I-026, still open); `?sky=off` and `?milkywaybrightness=` override. Since T-060 (`cbc920d`) the default star file is the committed HYG v4.2 naked-eye set (`src/assets/stars/hyg-v42-naked-eye.json`, CC BY-SA 4.0 on the star file only, the code is MIT; `STAR_SOURCES`, `DEFAULT_STAR_SOURCE = "hyg"`); HYG is the only star catalogue (the `?stars=` switch, the Yale file and the star-source choice were removed in O-017 T-067), and `checkStarAsset` in the public-build validator requires a complete licence record on the star file and its bytes in `dist/`. The one Milky Way picture is ESO eso0932a (CC BY 4.0, owner 2026-10-16), in the galactic frame and built on first need; the NASA deep star map, `SkySettings.source` and `?skymap=` were removed in O-017 T-068. `SkyView` is a camera-following group drawn first with depth off, so it never enters State. Positions use J2000 EQJ and galactic frame maths (`src/assets/sky.ts`; the pole constants are Astropy's, checked against the star file's own galactic coordinates). `App` appends a `sky` shell item to every experience's list, with provenance citing the star file and the picture. Developer-mode canvas attributes `data-sky-stars` and `data-sky-probe` expose it to browser checks. Local-data convention: fetched files (now the GMN orbit files only) live under git-ignored `data/local/`, the fetch tool is committed under `tools/data/`, and a production build never reads `data/local/` (the public-build validator now also checks that none of it ships by hash, text window and path). CAMS was dropped in O-017 (T-067) because its terms are silent (T-051); the permission email to its investigator is no longer needed.

**Rebuilt on the public API (O-042 T-176; read this first, the rest of this entry is the history it replaced).** `buildShowerScene` makes each shower with public `Scene` calls: `addBody` for the Sun, Earth (`orbit`, `enlarge`, `color`), Mercury to Jupiter and the parent (a catalogued comet by id, or `addBodyFromElements` for Phaethon), `addActivity` (rate curve, peak, published/modelled provenance spans), `addGroup` (the measured orbits, seed, clump when the settings state a share above 0, dot size, refill, `refillSliceMs`, a `rate` readout), `addEvents`, `addStoryPanels`, `setTimeline` (span, rates, opening rate, `loop`), `setScale(trueScale)` (which offers True and Solar system once a body is enlarged, T-177), `camera.setReach` and `camera.lookAt(..., { up })`. The site turns `buildShowerScene(...).toDefinition()` into the app's definition with the page label and the shower switch; `main.tsx` no longer loads the planet series first (`toDefinition` defers the Sun-orbit lines until they load, T-177). Gone with it, by Decision 1: the orbit-set buttons, `?orbits=` and `?span=` (the stream always shows all orbits; the published counts and rule stay in its known limits), `showerComposition`/`parentSamplingOf`/the hand-built path layers, `alternates`, and the Developer extras. Decision 4: the radiant is a line in the stream's description, the rate is a card bar. Decision 6: the camera menu is automatic. The old definitions' look is held by `tests/rebuildComparison.test.ts` against `tests/fixtures/showers-before-rebuild.json`. **Shower builder (T-038, T-039, T-055).** `src/experiences/showers/` builds an experience from `data/showers/<name>.json` (since O-024 T-091 one `?experience=showers` demo; `&shower=<name>` picks a file, the lowest `order` opens by default, and the glob in `src/main.tsx` means a new file needs no change there; `showerChoice.ts` chooses, the switch is a top-bar control that rebuilds in place (T-153, below), and only the chosen shower's measured orbits and story panels are fetched; the old `shower-perseids` and `shower-geminids` addresses are gone with no redirect; T-092: `timeline.yearStartUtc` starts the year, and the demo opens on 21 September 2019, with Phaethon's panel moved to 1 Nov 2019). It is outside the generic-name check by design: shower names live in settings and the builder, never in core, assets, shell or generic app. The settings supply the radiant, window, peak, rate samples, parent, stream colour and look; the stream itself is the measured GMN list drawn through `createListedOrbitGroup` (no invented members), with `stream.quality` and `?orbits=all|reliable` choosing the full set or the Q >= 15 degree and velocity-error <= 10% cut (counts stated in the panel). Further design points: (a) `showerComposition(settings)` lists the Sun and every catalogued body circling it, so no named composition is needed in `src/assets/compositions.ts`; (b) `src/main.tsx` builds a shower after `loadMeasuredOrbits` and the chosen story's panels (O-030 T-152: the eager `PANEL_FILES` glob is gone; the entry's lazy `STORY_PANELS` glob serves showers as it does planets, `loadShowerPanelsFile(settings, lookup)` raises the same `ShowerSettingsError` for a path naming no file, and `buildShowerDefinition(settings, load, set, panelsFile?)` takes the loaded file) (the dev server reads `data/local/` first, then the story's shipped copy; a production build reads only the shipped copy), and `buildShowerDefinition(settings, MeasuredLoad)` takes loaded, absent or invalid, as `loadStarCatalogue` does for the sky; (c) the parent's eccentric sampling is derived from the catalogue body's own trajectory plus the published a and e (`parentSamplingOf`), not imported by name; (d) peak instants are derived values: the settings give the published solar longitude, and the instant is computed from it with the formula the browser check uses (I-027: the IAU MDC solar longitude is J2000, so it is compared with a J2000 formula, no general precession); (e) the dot opacity (0.9) is not a setting (it would need an optional `opacity` on `GroupLayer`); (f) in-place switch (O-030 T-153): `SwitchControl` calls `onOpenAddress` (via `App`/`switcherOf`); the entry pushes history, shows the boot loader (`showBootLoader` rebuilds the cover from the page's own markup; the next scene's first frame hides it), rebuilds with `chooseDefinition` from the address and remounts `<App>` by key. `popstate` does the same without pushing; the newest request wins, so a slow earlier one is dropped. The planets switch uses the same path. Shared GPU pictures are disposed on scene unmount (`useReleaseSharedTextures` in `sceneContentsHooks.ts`, called from `SceneContents`): `releaseGlowTexture()` (glow picture and Three's one Sprite geometry, `bodyDraw.ts`), `releaseAnchorSprite()` (`TrackedBodyView.ts`) and `useBodyTexture`'s own dispose, because a renderer keeps its GPU copy in tables keyed by the object, and a shared object that outlives the scene would keep the old renderer, canvas and page DOM alive (heap grew about 2.6 MB per switch before, then levelled at 32.9 to 49.6 MB over 20 switches). Caches kept on purpose: planet series models (`planetSeries.ts`), the sky star catalogue request (`sky.ts`), the measured-orbit requests (`measuredOrbits.ts`, one per shower opened) and the weakly keyed `showerBasics` and `sceneBodySets`. The first-load limits: the showers pages list only the chosen shower's panels chunk (`storyPanels` option in `load-budget.mjs`, found through the app script's lazy map); Perseids 9.94 MB raw / 6.99 MB gzip (limits 10,070,000 / 7,040,000), Geminids 12.43 / 7.79 MB (12,680,000 / 7,890,000), measured 2026-10-23; re-measured in O-042 T-176, below. The browser journey's Geminids switch step is unrun until the Full Objective Check.

**Bodies from settings (T-055).** A settings file may define its parent (`parentElements`: elements and epoch, frame, radius, accuracy, source). `src/core/elementsBody.ts` turns that record into a definition and a two-body binding; `extendCatalogue` (`src/assets/catalogue.ts`) adds it to a copy of the catalogue. `ExperienceDefinition.catalogue?` (and `catalogueOf`) lets an experience carry its own catalogue; `createSceneResolver`, `catalogueItem`, the scene runtime and the path validators take one, defaulting to the built-in. "Planet" is decided by a sphere visual because there is no definition category. Known limit: PathView's explicit-centre validator still checks only the built-in catalogue. The first Geminids attempt (parent not catalogued) was a FINDING; this capability was the repair.

**Presentation settings added during the Perseids reworks (T-038).** Each is optional and defaults to the old behaviour: `ExperienceDefinition.loop` (and `SimulationClock.wrapWithin(window)`, wrapping a playing clock inside the bounds by whole window lengths, never while paused); `ExperienceDefinition.viewUp` (`"equatorial"` default or `"ecliptic"`; `src/app/viewUp.ts` gives the render-frame up from the engine's own ecliptic-to-EQJ matrix, no State rotated); the shower `timeline.span` (`"activity"` or `"year"`) and rate; `look.refillAfterHours` (the group refill span; 72 for Perseids after a measured frame-rate fix); `BodyVisual.emissive` and `glow`, drawn by `bodyDraw.ts` (an unlit sphere and a camera-facing additive halo sized from the disc), with a marker-kind emissive body framed by its sphere radius (`sphereRadius`, so the zoom stops outside the Sun at 1.15 radii, 800,055 km); `ExperienceObject.showLabel` and `?labels=`; one planet enlargement setting (`look.planetExaggeration`, 400) for the solar-system scale; a Sun texture (Solar System Scope 2k map, CC BY 4.0, recorded in `docs/DONOR_PROVENANCE.md`; its orientation is a visual stand-in). The Earth label of a shower stays visible at long range through `labelMaxDistance` set to the far plane.

**Measured orbits: GMN only (T-056, I-030, O-017 T-067).** The Global Meteor Network (CC BY 4.0) is the only source of measured orbits. CAMS was the first source (T-038) and was removed in O-017 along with `?source=`, the source buttons (the Developer switch now offers only the orbit set, `?orbits=`) and `offeredSources`; the settings now require `stream.sources.gmn` (months, licence and the `ruleNote` that maps GMN's Qc and Vgeo-sigma columns to the reliable cut) and have no `stream.source`. `tools/data/fetch-meteoroid-orbits.mjs --months ...` reads GMN into the file shape `loadMeasuredOrbits` expects. Shippable copies are committed at `data/stories/<story>/gmn-iau-<code>.json` and read through a glob; the file declares a licence that allows shipping or the load is reported invalid. The shipped files use a lossless column layout (T-070): `provenance.layout: "columns"` stores one array per entry of `provenance.columns`, the epoch column as differences from the row before, and drops the columns the app never reads (`SHIPPED_ROW_COLUMNS`); every value is unchanged, and `parseMeasuredOrbits` reads either layout. The listed-orbit group and `PointGroup` are unchanged by this.

**Story panels (O-015: T-059, T-061, T-062, T-087, T-088, T-089).** Story panels are story data; the engine holds only a generic contract. `ExperienceConfig.storyPanels?: StoryPanelSet` (`src/shell/experience.ts`) carries `panels`, `pauseSeconds` (default 6, at most 20) and `autoOpen` (default true). `parseStoryPanels(raw, lookup)` (`src/shell/storyPanels.ts`) validates a story's settings and throws `StoryPanelError` naming the panel and field: each panel has an `id` (unique), `at` (exactly one of `utc` ending in Z, `event` or `anchor`, resolved through `PanelLookup`), `title`, `body` lines, an optional `details` list (validated like `body`, default `[]`; exact figures and measured-versus-reconstructed notes, O-015 Decision 5), a `badge` (`observed`, `modelled` or `illustrative`), non-empty `sources` (PROV-01) and an optional `object`, checked against the experience's object ids; an optional `window` rejects a panel outside the timeline. `CrossingTracker`/`panelsCrossed` open a panel only when forward, playing time crosses it (a seek calls `rebase`, a rewind or loop opens nothing), and `useStoryPanels` holds one open panel at a time, pauses playback for `pauseSeconds` and resumes on its own, on Continue or when the viewer presses Play. `StoryPanelView` is a side panel on desktop and a swipe-dismissible sheet above the timeline on phone (ported from Planetary Explorer, credited in `docs/DONOR_PROVENANCE.md`); below the plain story it shows one folded section, `Sources` (`src/shell/Sources.tsx`, shared with the information panel), labelled "The details and sources" when the panel has details and "Sources · n" otherwise, closed by default. The body copy follows a plain-words voice (O-015 Decision 4) enforced by tests (two to four sentences, at most one number, no acronyms, every body number repeated in `details`; `tests/storyPanels.test.ts` also proves no fact was lost from the pre-rewrite copy). A panel naming an object gets a tappable marker: `SceneControls.storyMarkers`/`onStoryMarker`/`openStoryPanelId`, drawn by `StoryMarkerLayer` (`src/app/StoryMarkers.ts`) at the object's projected position. Markers group by object (`groupStoryMarkers`): one marker per object carries every panel naming it (`data-panel-ids`), and `panelForMarkerPress` opens the panel the clock has reached, or the next one in time order when one of that object's panels is open (wrapping); the marker layer receives the clock time. Panels are not `TimelineEvent`s and no `src/core/` file changed. Every demo has a story: Apollo reads `data/stories/apollo11/panels.json` (`buildApollo11Experience(mission, panels)`, events and anchors as the time lookup); Jupiter–Io passes `data/stories/jupiter-io/panels.json` through `parseStoryPanels` in `jupiterIo.ts` (the Earth–Moon story went with that demo, O-024 T-093). A shower's settings gain optional `story.panels`, either a repo-relative `data/stories/<story>/panels.json` (`PANELS_PATH`, resolved by an eager glob over `data/stories/*/panels.json` in `showerDefinition.ts`, so a shower page bundles every story's panels file, a few kB; narrowing it would need the generic path to know shower stories by name, so it is left as is) or the panels object inline; the file is validated against the full default (year) timeline so a data mistake still throws, then filtered to the visible span (a viewer who narrows `timeline.span` just loses panels outside it). Perseids and Geminids carry three panels each (`tests/showers.test.ts`, "story panels carried by shower settings", proves a made-up shower gains panels from settings alone, ARCH-03). Browser coverage: `browser-story-panels.mjs` (every story; details folded then shown; the shared Eagle marker opens each of its panels).
